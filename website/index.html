“Open that for me.” It opens next to the agent.

Put it right, left, above or below, in a terminal's place or in a window of its own, and drag it between them. The terminal keeps the keyboard, and Pitwall doesn't jump in front of the app you're in.

⌘S

Read

Text and code with their colours and Find, Markdown as code or preview. Images (PNG, JPEG, GIF, WebP, SVG) fitted, at 100 % or zoomed, and an SVG switches between its picture and its source. The tree and the Review list fold away or drag wider.

Quick fixes

Edit a text file where it's shown and save with ⌘S, with undo and Replace. If the agent changes it while you have edits, choose Keep mine, Take theirs or Show difference: nothing is overwritten without asking. Files of agents on this computer; agents still can't write through Pitwall.

Web pages

Ask for a page, a local dev server or an empty browser (Pitwall's MCP tool show_web, or pitwall open --web). The agent gets nothing back from the page and can't click, type or read anything in it. Pages use the system's web view, not a browser: WebKit on macOS, WebView2 on Windows, WebKitGTK on Linux; one page per tile, no tabs. Off in Settings → Agents. More

PDFs

macOS only for now: pages, zoom and Find, drawn by the system's PDF engine. On Windows and Linux a PDF says it can't be shown yet and offers Open in default app.

Where it works

The files come from where the agent works now, also a worktree it moved into, with that branch, its git status and Show diff. Claude Code, Codex, Copilot CLI, Qwen Code, Amp and opencode get Pitwall's MCP server (show_files, show_folder) at each launch, without edits to your config files; Gemini CLI and Cursor Agent get an entry in their own MCP file when you ask in Settings → Agents; Aider and shells use pitwall open. Tried by hand with Claude Code on macOS; the other agents' routes are tested in code, not yet against each CLI. How

Answer

Accept and Reject for plain yes/no prompts, Accept all when several ask, Open for anything else. Or use the keyboard once the cards are open: arrows, Enter, Esc and text go to the first card's agent, and Pitwall still doesn't come forward.

Nothing blind

Pitwall reads the agent's screen again before it sends a key, and sends nothing if the prompt is no longer the one you saw.

Your size

Drag the tile anywhere, and the cards' edges or corner for wider cards or more of each terminal; the size is kept, and a double click on an edge goes back to the default. Liquid Glass on macOS 26 with the Glass look. Off in Settings → General.

Tested

Accept and Reject keys were checked against Claude Code and Codex; the other agents' are written from their prompts and not yet checked against the real CLIs. Run on macOS; the Linux and Windows builds have the control, but it hasn't been run there.

Work login, personal login. Each project on the right one.

Run Claude Code, Codex, Gemini CLI and Copilot CLI on more than one login, say a work and a personal subscription. Each project picks the login its agents run on, per tool: in its Accounts…, or by dragging it onto another account in the sidebar. Its running agents of that tool restart on the new login right away, and Claude Code and Codex pick up their conversations there. The project's web pages open in the browser account it picks there too.

An account

One login of one tool: a name and the folder the tool keeps its login in (CLAUDE_CONFIG_DIR, CODEX_HOME, GEMINI_CLI_HOME, COPILOT_HOME); Default is your own. A work Claude Code and a work Codex are two accounts, each picked on its own. Cursor Agent, opencode, Amp, Aider and Qwen Code have no setting that moves their login, so they run on one.

Per project

A project's right-click → Accounts… sets the account its new agents use for each tool, a git identity for its commits and pushes, and a browser account for its web pages. A profile (Settings → Profiles) bundles these picks under one name, such as Work, and a project then picks the profile. New agent can pick another, and an agent's right-click → Run on account moves just that one. With the sidebar grouped by account (Settings → General), drag a project or an agent onto another account.

Running agents

Moved agents restart on the new login at once. Claude Code and Codex resume their conversation; the other tools start a new one. Settings → Accounts shows who each account is logged in as, Codex's plan limits and Claude Code's tokens.

Stays here

Accounts are login folders on this computer, listed in ~/.pitwall/accounts.json. There is no Pitwall account: logins and usage are read from the tools' own files, and nothing is sent anywhere. Agents on this computer only.

Pit stop

⌘Q closes the window, not your agents. Their terminals keep running and come back with the scrollback on the next launch.

Native

A Rust app drawn on the GPU with GPUI, Zed's UI framework. No web view: terminals are parsed and drawn in the same process, so a wall of busy agents stays light. More

Also

Claude Code and Codex on more than one login, per project or per agent. Sessions on agw VMs show up next to local agents, and a pitwall CLI lets you or an agent add more; anything that touches another machine waits for your OK in the app.

Race Engineer

Optional: an assistant agent for Pitwall itself, on the agent and subscription you already use. Ask it to set up agw, arrange spaces or tune settings; it works through the pitwall CLI, and risky steps still wait for your OK. Nothing runs until you open it.

Coming
