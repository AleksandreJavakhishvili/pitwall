How it works

Pitwall hosts terminal coding agents. It isn't an agent itself: it never rewrites prompts or decides what an agent does. This page covers the parts the home page only names.

Flags

Each agent has one flag, shown in the sidebar, its pane header and its Wall tile. Within a project, agents sort needs you → done → working → idle, then the rest.

Example agents and their flags
PosAgentFlagDetail
1tests▲Needs youBash: pnpm test --run src/cart
2docs⚑Done finished a turn you haven't looked at
3api-fix◐Working2 prompts in Next up
4refactor●Idlewaiting for a prompt
5scratch■Stoppednot running; Restart resumes it
  • Needs you: a permission prompt or a question. Amber row, a bar along the bottom of the window, counted on the Dock badge. ⌘J jumps to the next one.
  • Done: finished a turn you haven't looked at. Looking turns it idle.
  • Working: output is flowing, or the agent's hook says it's busy.
  • Idle: waiting for a prompt. Unknown (?) means there's no signal yet.
  • Exited / stopped: the process ended, or it was loaded after a restart and isn't running.

When the window isn't focused, needs you and done also post a native notification.

How it knows

  1. Hooks, when the agent has sent one this run. Claude Code gets its hooks per launch through --settings; ~/.claude/settings.json is never edited. Codex hooks are opt-in, and ~/.codex/hooks.json is backed up first.
  2. The screen. A headless copy of each terminal is matched against per-agent TOML rules, adapted from Herdr's detection manifests (Apache-2.0). Always on.
  3. Activity. For any other CLI: output in the last ~1.2 s means working, otherwise unknown.

Hooks are never required.

Wall

⌘E shows every agent's terminal, grouped by project, blocked first. Tiles show the bottom rows of each terminal, where prompts wait. The Wall is view-only: it never resizes a terminal and never types. Click a tile to take over that agent; Esc comes back. A window left in Wall mode stays that way across restarts.

Next up

Each agent has its own queue in the right panel (⌘.). With Auto-send on, the first item goes once the agent has been done or idle for 0.8 s and you haven't typed in its terminal for 2.5 s. Text goes in as a bracketed paste, then Enter, exactly as written. Last sent stays under the queue.

Review

⌘R lists changes by agent, then file, in a side-by-side or inline diff. Pick All changes or one task: a single prompt, from send until the agent is done.

  • Per-task snapshots are written through a temporary index (GIT_INDEX_FILE), so your real index and working tree are never touched. Untracked files are included.
  • Click a line to comment. Send comments shows the composed prompt for editing first, or queues it if the agent is busy.
  • Commit & merge runs git merge --no-ff of the worktree's branch, only when you click. It refuses if your main checkout is dirty; on a conflict it runs git merge --abort and offers the agent an editable "rebase and resolve" prompt.
  • The diff editor is bundled, so Review works offline.

Terminals that outlive the app

Each agent's terminal belongs to its own pitwall-hold process, not to the app. ⌘Q closes the UI; dev servers and half-finished turns carry on, and the next launch re-attaches with the scrollback replayed. Only Stop, Restart, Remove or Quit and Stop Agents end a terminal. After a reboot, agents come back stopped, and Restart resumes the conversation for CLIs that support it.

Pitwall.app   UI, quit any time
   │ attach · write · resize · replay
   │ ~/.pitwall/run/hold/<agent>.sock
   ▼
pitwall-hold  one per agent, setsid, owns the PTY
   ▼
claude --session-id 7f3c…   still running

Stop / Remove → SIGHUP, SIGKILL after 1.5 s

Spaces and windows

Spaces are tabs of tiled terminals. Presets: 1, 2, 1 big + 2, 2×2 and 3×2, plus 3×3, 4×3 and 4×4 when the window can fit them, and Auto grid. Drag an agent onto a pane edge to split, onto the centre to swap. An agent sits in at most one pane; extras fold into a chip strip. ⌘⇧N moves a space into its own window, and layouts, windows and bounds come back on launch. Moving a terminal never restarts it.

Claude Code and Codex can start in their own worktree through the CLI's own flag (claude --worktree <name>, codex --worktree); Pitwall creates no branches or folders. Add your own kind with a TOML file in ~/.pitwall/agents/; override detection rules in ~/.pitwall/detect/.

Rules

Keep rules in ~/.pitwall/rules/, group them into named sets, and assign a set per project with optional extras per agent. Pitwall calls the rulesync CLI to write CLAUDE.md, AGENTS.md and the rest; it doesn't reimplement it.

  • Import from a project's .rulesync/, an existing CLAUDE.md or AGENTS.md, or a git repo.
  • Generated paths go into the worktree's .git/info/exclude, so they never show up in Review or a commit.
  • Agents in your main checkout only get rules when you tick the box.
  • Uses rulesync on PATH, or npx -y rulesync only if you enable it in Settings.

agw machines

If you use agw to run agents on VMs, its sessions show up in Pitwall next to your local agents, grouped by machine.

  • Works today: add an existing session and get its live terminal, its flag (from screen detection), Next up, stop and start. Diffs and Review run git on the VM through agw. New agent → Runs on creates a session on a VM with agw's own workspaces, users and templates.
  • Not yet: hooks and rules on VMs (status comes from the screen only), merging from Review, and deleting a session on the VM. Removing an agw agent from Pitwall only detaches it; the session keeps running there.

CLI and approvals

Settings → Install command-line tool links pitwall into ~/.local/bin or /usr/local/bin. It talks to the running app over a local socket and prints JSON (--human for text).

pitwall agent list
pitwall agent new --kind claude --project ~/code/api --name api
pitwall session list --provider agw
pitwall session add agw <vm> <session> --start

Today it lists and adds; it can't stop, remove or prompt agents. Anything that changes another machine (starting or creating a session on a VM) opens an approval dialog in Pitwall and the command waits for your answer. A denial exits with status 3. The app works out who's asking from the calling process, so an agent can't approve its own request.

First launch

A read-only scan: agent CLIs on your PATH, recent projects from Claude and Codex transcripts, VS Code and Cursor history and one level deep in ~/projects ~/code ~/Developer ~/src ~/dev ~/work, and conversations you can continue. Desktop, Documents and Downloads aren't enumerated; use Add folder…. Nothing changes until you tick a box. Details are in the quick start.
