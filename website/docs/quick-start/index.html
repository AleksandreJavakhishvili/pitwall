Quick start

Pitwall is a desktop app for macOS, Linux and Windows (preview) that hosts terminal coding agents and shows which one needs you. It is not an agent itself: it never rewrites prompts or decides what agents do. Download a build from GitHub Releases, or build it from source.

Install

macOS on Apple silicon or Intel (one universal build), Linux x86_64 and Windows x64 (preview). The download page has every file and the first-launch steps for each system. On macOS:

  1. Download the .dmg from the download page and drag Pitwall to Applications.
  2. Open it once with right-click → Open, then Open again in the dialog.

Why the extra step: releases aren't signed with an Apple Developer ID or notarized yet, so Gatekeeper blocks a double-click on the first launch. If macOS says the app is damaged, clear the quarantine flag instead:

xattr -dr com.apple.quarantine /Applications/Pitwall.app

Until builds are Developer-ID signed, macOS may ask again for folder access (Desktop, Documents) after you install a new version, because it sees each build as a different app.

A Homebrew cask is coming; it isn't published yet.

Build from source

You need macOS with the Xcode Command Line Tools, a Rust toolchain (rustup), Node.js and pnpm: the usual Tauri 2 prerequisites. Plus at least one agent CLI you're already logged in to.

git clone %REPO_URL%.git
cd pitwall
pnpm install
pnpm tauri dev                      # run the app with hot reload
pnpm tauri build --bundles app      # → target/release/bundle/macos/Pitwall.app

The build also compiles pitwall-hold (the per-agent terminal holder) and the pitwall CLI, and ships both inside the app bundle. To install the build into /Applications, see the README.

Running only pnpm dev opens the UI in a browser with mock agents and a simulated scan, which is handy for UI work. The demo on the home page is that mode.

First launch

Pitwall opens with a read-only scan. Nothing on your Mac changes unless you tick a box.

  • Agents on your login-shell PATH, each checked with --version only.
  • Projects from Claude transcripts, Codex sessions, VS Code / Cursor recent folders, and one level deep in ~/projects ~/code ~/Developer ~/src ~/dev ~/work. Desktop, Documents and Downloads aren't enumerated; use "Add folder…".
  • Conversations you can continue. The latest one per ticked project from the last 3 days is pre-ticked.
  • Running elsewhere — agents in other terminals. "Bring into Pitwall" is off by default; close the old terminal first so two copies don't run.
  • Rule files and Codex hooks status. Installing Codex hooks is a checkbox, and ~/.codex/hooks.json is backed up first.

Start Pitwall creates an agent per ticked conversation, resumed in its own folder, and tiles them in the All space. Settings → Scan again runs the same flow later and skips conversations that already have an agent.

Start an agent

⌘N opens New agent: pick a project, a kind (Claude Code, Codex, Gemini CLI, opencode, Cursor Agent, GitHub Copilot CLI, Qwen Code, Amp, Aider or Shell) and a name.

  • Separate worktree (off by default; Claude Code and Codex only) passes the agent's own flag — claude --worktree <name> or codex --worktree. Pitwall finds where the agent ends up working and uses that folder for status, diffs and Review. It creates no branches or folders of its own.
  • Rules picks a rule set to write through rulesync before launch. For agents in your main checkout this needs an explicit tick.
  • Agents launch through $SHELL -l -i -c, so they see the same PATH and config as your terminal.

Read the flags

  • ▲ needs you — a permission prompt or question. Amber, sorted first, counted on the Dock badge. ⌘J jumps to it.
  • ⚑ done — finished a turn you haven't looked at yet.
  • ◐ working — busy.
  • ● idle — waiting for a prompt.
  • ■ exited / stopped — the process ended, or it was loaded after a restart and isn't running.

Sources, in priority order: hooks (when the agent has sent one this run), then the terminal screen matched against per-agent rules, then output activity. When the window isn't focused, a blocked or done agent posts a native notification.

Next up

Type a follow-up in the right panel and press ⌘↵. With Auto-send on, the first item goes once the agent has been done or idle for 0.8 s and you haven't typed in its terminal for 2.5 s. Text is pasted exactly as written, then Enter.

Review

⌘R opens every agent's changes. Choose All changes or a single task, click a line number to comment, then Send comments to deliver one editable prompt. Commit & merge commits in the agent's worktree and merges its branch with --no-ff; it refuses if your main checkout is dirty and aborts cleanly on conflicts.

Quitting

Closing the window hides it; the Dock icon brings it back. ⌘Q quits the UI only — every agent keeps running in its pitwall-hold process and is re-attached next launch. To end everything, use the app menu's Quit and Stop Agents.

Files

Everything lives in ~/.pitwall/:

state.json          agents, queues, session ids
ui.json             spaces, layouts, windows
agents/*.toml       your own agent kinds
detect/*.toml       status rule overrides
rules/              rule library (rulesync format)
run/hold/*.sock     one socket per terminal holder
