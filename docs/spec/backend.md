# Backend behaviour


- **State dir** `~/.pitwall/` (Windows: `%APPDATA%\Pitwall\`; `$PITWALL_HOME` overrides both; on Windows every `*.sock` below is a named pipe derived from that path, `pitwall_proto::pipe`, only the user's account can open): `state.json` (agents, queues, session ids), `run/pitwall.sock`, `run/hold/<agentId>.sock` (terminal holders), `bin/pitwall-hook`, `agents/*.toml` (user agent defs), `detect/*.toml` (user rule overrides). Pitwall creates no worktrees or branches of its own (`worktrees/` only holds ones made by older versions; their agents keep working from the stored path).
- **Terminals live in holders** (architecture.md §9.1): every agent's PTY and process belong to its own `pitwall-hold` process (`crates/pitwall-hold`; protocol v1 documented in its `lib.rs`), which `setsid`s away from the app, serves `run/hold/<agentId>.sock`, and exits only after its child exits (3 s grace so the final status can be read). `session.rs` starts the holder with the launch command and environment below, then connects; it keeps the ring, `Screen`, fan-out, activity timing and paste logic. On app start, each persisted agent whose holder still answers with a running child is re-attached (history replayed, status running, nothing respawned). Pitwall housekeeping never kills a terminal; only Stop/Restart/Remove and "Quit and Stop Agents" send the holder `SHUTDOWN` (SIGHUP, SIGKILL after 1.5 s).
- **Holder binary**: `pitwall-hold` sits next to the app executable (`pitwall`): in dev after `cargo build -p pitwall-app -p pitwall-hold -p pitwall-cli` (`target/debug/pitwall-hold`), and in every bundle `scripts/package-app.sh` makes (`Pitwall.app/Contents/MacOS/pitwall-hold`, `/usr/bin` in the .deb and the AppImage, the install folder on Windows; docs/spec/gpui/packaging.md). Lookup (`pitwall_app::host::holder_bin`): `$PITWALL_HOLD_BIN`, the exe's dir, its parent (tests). An AppImage's holder is copied to `<data>/bin/` first so running holders outlive the mount. The `pitwall-cli` command-line tool ships the same way, and Settings links it as `pitwall` in `~/.local/bin` or `/usr/local/bin`. Up to v0.1.x the Tauri shell bundled both as `externalBin`s; same names, places and protocol, so the GPUI app re-attaches holders the Tauri app started (`host::tests::a_second_app_reattaches_the_first_apps_agents`).
- **Launch** through the `LoginShell` (`pitwall_core::shell`): `$SHELL -l -i -c 'exec <cmd> <args>'` on macOS (Dock apps lack the terminal PATH); on Windows PowerShell (`pwsh`, else Windows PowerShell; `$PITWALL_SHELL` overrides) runs `<cmd>` after refreshing PATH from the registry, and the shell kind is the interactive shell itself. The holder execs exactly this and passes its environment through. On Windows the holder re-spawns itself detached (no fork) and runs the shell in a ConPTY; Shutdown closes the pseudo console, then ends the process tree by pid. Env: `TERM=xterm-256color`, `COLORTERM=truecolor`, `PITWALL_ENV=1`, `PITWALL_AGENT_ID`, `PITWALL_SOCKET` (hooks), `PITWALL_CLI_SOCKET` (the `pitwall` CLI); remove `CLAUDECODE` and other `CLAUDE_CODE_*` session vars inherited from a parent Claude.
- **Claude**: pass `--session-id <uuid>` on create, `--resume <uuid>` on restart. Hooks go in via `--settings '<json>'` per launch — never edit `~/.claude/settings.json`.
- **Codex**: hooks live in `~/.codex/hooks.json`; only `install_codex_hooks` writes there (back up first, append Pitwall entries, keep existing entries). Session id comes from the SessionStart hook payload if present.
- **Hook relay** `~/.pitwall/bin/pitwall-hook` (Windows: `pitwall-hook.exe`, a copy of the `crates/pitwall-hook` sidecar; the hook command is its path with forward slashes, and Claude's `--settings` gets a file instead of inline JSON because PowerShell mangles JSON arguments). The sh script on macOS: exits 0 silently unless `PITWALL_AGENT_ID` and `PITWALL_SOCKET` are set; otherwise POSTs stdin JSON with `curl --unix-socket` to `http://pitwall/hook/<agentId>`. Never prints to stdout, always exits 0.
- **Hook mapping** (by `hook_event_name` in the payload): `SessionStart`→record `session_id`; `UserPromptSubmit`/`PostToolUse`→working; `PreToolUse`→blocked if `tool_name == "AskUserQuestion"` else working; `PermissionRequest`→blocked; `Stop`/`Interrupt`→done.
- **Sending text**: `ESC[200~` + text + `ESC[201~`, then `\r` ~200ms later. Never modify text.
- **Auto-send** (default on): when status is `done`/`idle` for ≥0.8s, queue non-empty, and no user keystroke in the last 2.5s → send next item.
- **Diffs**: the Changes list and the +/- counts match `git status`: `git diff --numstat HEAD` (staged + unstaged) + untracked files. `base_commit` (HEAD at creation) is kept only as Review's "since the agent started" baseline. Git runs with `GIT_OPTIONAL_LOCKS=0`. Refresh pace (perf.md "Git refresh"): where the provider can watch files (`ProviderCaps.fs_events`: local), the agent's checkout is watched (one `notify` watch per checkout, shared by its agents; git internals except HEAD/index/refs, dependency/build folders and git-ignored paths don't count) and git runs only when something changed (at most every 3 s), plus a safety poll while the agent works or prints (60 s; 30 s on inotify, which skips dependency folders by name); at most 64 checkouts are watched, and an OS that refuses (inotify limits) or a watch that breaks falls back to polling. Elsewhere (agw) and as that fallback: ≤ every 3 s while active, backing off to 30 s while nothing changes.
- **Worktrees** (optional per agent, see worktrees.md): the agent's own flag from its definition, `worktree_args` (`claude --worktree <name>`, `codex --worktree`; `{name}` = slug of the agent name, made unique against `git worktree list`), added on fresh starts only. The record keeps `worktreePending` until Pitwall finds where the agent works: (1) the hook payload's `cwd`, (2) the process cwd via `lsof -a -d cwd -p <pid> -Fn`, (3) a `git worktree list --porcelain` entry that wasn't there before the launch (prefers one named after `{name}`). A candidate must be a linked worktree of the project (not the main checkout, not another agent's). The ticker looks every ~1.5s for 2 min after a launch, off-lock; hooks can still find it later. Found → `worktree = { repo, path, branch }`, `cwd` = that folder (status, diffs, Review, resume all run there), `base_commit` = merge-base of the worktree's HEAD with the project's current branch, rules are written into it. Branch for merge = `git branch --show-current` in the worktree (stored one as fallback). `remove_agent(deleteWorktree)` uses `git worktree remove` without `--force`; the branch is kept.
- **Window**: closing the window hides it (agents keep running); Dock click reopens; ⌘Q quits the UI only — agents keep running in their holders and are re-attached on the next start. App menu → "Quit and Stop Agents" ends them all and quits.
- **Attention**: when an agent becomes `blocked` or `done` and the window isn't focused → native notification. Dock badge = number of `blocked` agents (Windows: taskbar overlay icon + tray tooltip; closing the window leaves Pitwall in the tray).
